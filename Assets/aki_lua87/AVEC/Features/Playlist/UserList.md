# 保存リストと特殊リスト

PlaylistSetupのInspectorで「再生キュー」「再生履歴」「保存リスト」を個別に選択できます。
変更は特殊リストの表示・設定に限定され、既存の動画データ、テーマ、プレイヤー接続は再生成しません。
チェックを変更するとその場で反映されます。反映ボタンの操作は不要です。

保存リストではURLを入力して追加し、行を押すと動画詳細が開きます。
詳細画面から再生・キュー追加・「リストから削除」を操作できます。
最大32件、URLはhttp(s)かつ2048文字以内、重複URLは登録しません。全件を縦スクロールで表示し、ページ送りはありません。
再生には通常のプレイヤー権限が適用されます。リストへの登録・削除はプレイヤーの操作権限とは独立です。

## 永続化

同じシーンの各UIは、1つの`CommonVideoPlaylist User Data`を共有します。
このオブジェクトには`VRCPlayerObject`、`VRCEnablePersistence`と`PlaylistUserData`があります。
プレイヤーごとのコピーにURL、タイトル、項目IDを同期変数として保持し、追加・削除・タイトル更新時に保存を要求します。
ローカルプレイヤーの`OnPlayerRestored`後にのみ編集を許可します。

保存先はユーザーアカウントごと・ワールドごとです。別インスタンス・別端末でも同じワールドなら復元対象です。
リストのUIは自分のデータを表示しますが、保存用同期データは秘密情報の保管用ではありません。
PlayerObject保存枠は他アセットと共有の100KBです。このリスト自体にも保守的な48KBの推定上限を設けています。
共通プレイリストUIのStatus・エラーメッセージは非表示で、容量超過時も画面に通知しません。追加できない場合は復元完了・URL・重複・件数・容量を確認してください。保存完了・再入室復元はアップロード済みワールドで確認してください。

**公開後は保存用オブジェクトを削除・作り直したり、Network IDを変更したりしないでください。**
既存の保存データとの対応が失われる場合があります。特殊リスト設定の反映処理は既存オブジェクトを再利用します。
保存リストを無効にしても保存用オブジェクトとデータは削除しません。
複数UIが同じプレイヤーに接続されている場合、履歴は1つでも履歴を有効にしたUIがある間記録されます。

## 任意のYTTL連携

YTTLは基本機能に不要です。タイトル取得だけを追加したい場合は、VizVid同梱YTTLを導入済みのプロジェクトに
別パッケージ`AVEC-Extension-YttlTitles`を導入してください。VizVid用Connectorは不要です。
拡張導入後、PlaylistSetupの「YTTLタイトル取得（拡張）」でVizVid同梱の`YttlManager`を指定します。
同じシーンに1個だけあれば「シーン内のYTTLを接続」でも設定できます。
旧版からの更新・連携解除は[拡張のREADME](../../Extensions/YttlTitles/README.md)を参照してください。
VizVidのプレイヤーが既にあるだけでは、編集時にYTTL Managerが実体化していない場合があります。
その場合はVizVid付属の`YTTL Manager.prefab`をシーンへ配置して指定します。

URLの追加時に`LoadData`を呼び、動画を再生せずにタイトル取得を要求します。
未設定・未対応URL・通信失敗時もURLを表示してそのまま利用できます。
取得に成功したタイトルは最大256文字で保存します。次回訪問時は保存済みタイトルを表示します。
削除した項目への遅延応答は項目IDで除外します。
YTTL本体とネイティブプレイヤーのソース・Prefabは変更しません。
対応サイトやAllow Untrusted URLs等の条件はYTTLおよびVRChatの設定に従います。

## 手動確認

1. 2つのUIから同じ自分のリストが見えること、追加しても再生が始まらないことを確認。
2. 行の選択で動画詳細が開き、詳細から再生・キュー追加・削除ができることを確認。プレイヤーロック時の権限も確認。
3. YTTL対応URLを追加し、再生前にタイトルが反映されることを確認。
4. 追加直後に削除し、タイトル応答で復活・別行への誤反映がないことを確認。
5. アップロード済みワールドから退出・再入室し、URL・タイトルと削除結果の復元を確認。
6. 別ユーザーでは独立したリストになることを確認。
