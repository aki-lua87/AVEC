# AVEC Playlist

0.2.0ではコンパクトUI、再生順アイコン、カラーテーマ、再生・停止・音量操作、キューを追加しました。CommonGestureRemote連携の次／前・タブ操作APIも継続して利用できます。

同じPlaylistDataを、iwaSync3 / KineL / VizVid / YamaPlayerに接続した複数のUIで共有できます。各UIは1台のプレイヤーに接続します。タブ・スクロール・選択表示はローカル状態です。

## 導入

配布先は `Assets/aki_lua87/AVEC/Features/Playlist/` です。既存の参照互換のため、名前空間は `aki_lua87.CommonVideoPlaylist`（エディタ用は末尾に `.Editor`）を維持しています。

旧版からのフォルダー移行は [MIGRATION](../../Core/MIGRATION.ja.md) を参照してください。GUIDを保持し、Prefabやシーンを作り直さず更新します。

1. VRChat Worlds SDK 3.10.5を導入したUnity 2022.3.22f1プロジェクトにAVEC-CoreとAVEC-Playlistをインポートします。
2. 使用するプレイヤー本体を別途導入し、対応するAVEC-Connector-プレイヤー名-Playlistだけをインポートします。**未導入プレイヤー用Connectorは入れないでください。** プレイヤーを削除するときは対応Connectorも削除します。
3. `Prefabs/CommonVideoPlaylist.prefab`をシーンに配置します。
4. ルートのPlaylistSetup Inspectorで接続を確認します。候補1件は自動接続、複数件は候補ボタンから選択します。接続先フィールドを変更した場合も即座に接続を更新します。
5. 「新規プレイリストを作成」で、このUI専用の空のPlaylistDataを作成します。配布用DefaultPlaylistが指定されている場合は「プレイリストを編集する」でも専用データを作成します。既存のPlaylistDataを「プレイリスト」欄に指定して共有することもできます。
6. 専用の「プレイリスト編集」ウィンドウで、左側のタブと右側の動画を編集します。＋／－で追加・削除、ドラッグで並べ替えができます。
7. 右上の「保存」でデータを保存し、同じデータを使う開いているシーンのUI（非アクティブなものを含む）へ自動反映します。シーン自体の保存は通常のUnityの保存操作で行ってください。

編集内容は保存するまで元データやシーンに反映されません。未保存のままウィンドウを閉じるとUnityの保存確認が表示されます。タブや動画の編集はUndoに対応し、保存時のデータ変更とUI反映もまとめてUndoできます。データアセットのInspectorからも同じ編集ウィンドウを開けます。

接続候補はInspectorで更新されるため、旧「再検出」は不要です。未接続で候補が1件のときだけ「見つかったプレイヤーに自動接続」を表示します。旧「接続を適用」も通常操作では不要で、接続設定に問題があるときだけ「接続設定を修復」を表示します。

同じデータアセットを複数のPlaylistSetupに指定できます。Playモードへの移行時とVRChat SDKのワールドBuild開始時に、ロード済みシーンの全インスタンスへ自動で反映します。閉じているシーンも、そのシーンを開いてPlay/Buildする時点で更新されます。Prefabアセットにはシーンのプレイヤー参照を保存しません。

配布用の `Samples/Playlists/DefaultPlaylist.asset` はタブ・動画・URLを含まない空の入れ物です。Prefabを複数配置しても、各UIで新規作成したデータを割り当てれば独立して編集できます。同じデータを共有中の場合はInspectorと編集ウィンドウに共有数を表示します。この作成操作はUnityのInspector上で行います（ワールド内で.assetを作成する機能ではありません）。

## キュー

左側タブの一番上に「キュー」を表示します。選択すると右側の先頭に「＋ 動画を追加」、その下に再生待ち一覧を表示します。「動画を追加」でURL入力を開き、http(s)の動画URLを登録できます（最大2048文字）。直接追加した項目はURLを表示名にします。プレイリストの動画行の「＋」からも追加できます。個別削除・全消去・ページ移動・先頭からの再生に対応し、最大32件、1ページ6件です。空き状態では追加後に再生を開始し、再生中は自然終了を待ちます。「全消去」は再生待ちだけを消し、現在の動画は停止しません。停止後の再開にはキューパネルの「再生」を使います。

キューは接続先プレイヤー単位で共有し、操作権限は接続先に従います。別プレイヤー間では共有しません。ローカル再生モードではキューもローカルです。プレイリストから追加した項目はベイク済み動画を参照し、直接入力した項目はURLを同期します。追加順に再生し、順再生／ランダム設定の影響は受けません。キュー再生が始まるとタブの連続再生より優先し、使い切ったら終了します（元のタブ連続再生へは戻りません）。

これは本アセットの共通キューです。iwaSync3／VizVid本体のキュー一覧を読み取る機能ではありません。本体に既存キューがあればその再生を優先し、競合するURL要求を避けます。本体に要求を渡した項目は再生待ち一覧から外れます。単曲リピート・終了通知のないライブ配信では自動で次に進みません。読み込み失敗時にも自動で項目を飛ばしません。

複数クライアントの同時編集・途中参加・所有者退出、本体キューとの併用はVRChat内で手動確認してください。編集時の構成・コンパイル確認のみ実施しています。

サンプルは `Samples/Playlists`（空のDefaultPlaylist）、`Themes`（VRC Slateと4色）、`Scenes`（検証シーン）に分けています。旧「コンパクトなレイアウトを使用」はサイズ・位置・フォント・テーマなどを初期配置へ戻す処理だったため、通常のInspectorから削除しました。新規UI作成時の内部処理としてのみ使います。

## 動的プレイリストExtension

YouTube取り込みと実行時のタイトル更新は、別途導入する [DynamicPlaylist Extension](../../Extensions/DynamicPlaylist/README.ja.md) に移動しました。導入すると本体の編集画面とInspectorに専用画面を開くボタンが表示されます。

## UIの調整

World Space Canvasは900×560、Scale 0.00135（幅約1.215m、高さ約0.756m）。旧UIから幅約37%、高さ約38%小さくしました。動画行に通し番号は表示しません。ルートのScaleで設置サイズを調整できます。左右の一覧は独立したScrollRectとドラッグ可能な縦スクロールバーです。VRCUiShape、GraphicRaycaster、BoxColliderを備えています。

DefaultTheme.assetの表示名は **VRC Slate** です。VRChatのUIを参考にしたスレート系背景とシアンの独自配色です。`Samples` に **Mint / Periwinkle / Amber / Orchid** の4テーマも同梱しています。PlaylistSetupの「カラーテーマ」にPlaylistTheme Assetを指定します。テーマを複製、またはAssets > Create > AVEC > Playlist > Color Themeで作成し、背景・パネル・ボタン・選択・アクセント・文字・補助文字を編集できます。同じThemeを複数UIで共有できます。テーマの編集・割り当てで開いているシーンへ色を反映します。プレイリストデータの保存ではUI全体のテーマ・サイズ・位置を再適用しません。

ヘッダーには接続先のプレイヤー種類と名前、AudioLinkの接続状況を表示します。音量バー左はスピーカーアイコンです。AudioLink表示は読み取り専用で、AudioLink本体や音源の設定を変更しません。本体未導入は「未導入」、シーンにない場合は「未配置」、接続先プレイヤーのAudioSourceがAudioLinkの左右いずれかの入力に指定されていれば「接続中」と表示します。停止中でも入力の参照が一致していれば接続中です。AudioLinkの音出力や効果の有効性を保証する表示ではありません。

AudioLinkを後から配置・削除した場合はInspectorの「AudioLinkの接続状況を更新」で参照を再検出できます。Play/Build前にも再検出します。実行中の音源切り替えは約0.5秒ごとに表示へ反映します。AudioLink本体は別途導入してください。[AudioLink公式](https://github.com/llealloo/audiolink)

非表示の`Templates`にタブ／動画行のテンプレートがあります。Text、Image、Button、LayoutElementを編集すると次回反映時に全行へ適用されます。生成済みのContent内の行は再生成されるため、行デザインの変更はテンプレートへ行ってください。ヘッダー、背景、余白などは通常のUnity UIとして直接編集できます。日本語表示にはZen Maru Gothic Regular（SIL OFL 1.1）を同梱し、../../Core/Fonts/OFL.txtにライセンスを含めています。

### 再生・停止・音量

下部の▶で再開します。停止後は同じタブで最後に選択した動画、未選択なら先頭の有効な動画を要求します。■でネイティブ再生と共通UIの連続再生を停止します。再生・停止はプレイヤー本体の権限と同期に従います。音量スライダーは自分の環境のみ変更し、プレイヤー本体やリモコンからの変更も表示へ反映します。表示値は0～100%の絶対値で、iwaSync3などのネイティブ最大音量制限は維持します。

右上の平行矢印は順番再生、交差矢印はランダム再生です。交差矢印をアクセント色で表示します。

UI参照や手動での再生成はPlaylistSetupの「詳細設定（UIデザイン・参照）」にまとめています。テンプレートを変更した場合は「テンプレートからUIを再生成」で反映できます。通常のプレイリスト編集では編集ウィンドウの「保存」だけで反映します。

選択表示と「Requested」は、プレイヤーAPIへ要求を渡したことを示します。**再生開始・再生成功を示す表示ではありません。** 読み込み結果、映像、実際の再生状態は接続先プレイヤーで確認してください。検索、サムネイルはありません。

## 動画終了後の連続再生

動画を選択すると、その動画から同じタブ内の並び順で連続再生します。最後の動画で終了し、別タブや先頭へは進みません。空URL・HTTP(S)以外のURLの行はスキップします。表示中のタブを切り替えても、再生中のタブの順序は変わりません。ワールドJoin時の自動再生は追加していません。

### ランダム再生

ワールド内のUI右上にある再生順アイコンで切り替えます。再生中の動画は止めず、次の動画から変更を反映します。順番再生へ戻すと現在の行の次から進み、ランダム再生へ切り替えると現在の行を開始位置にして新しい一巡を始めます。切り替え前に再生済みの行も、新しい一巡の対象になります。

モードは同じプレイヤーに接続した共通UI間で共有し、同期再生では他の参加者にも同期します。停止やタブ変更後も選択したモードを維持します。変更には接続先プレイヤーの操作権限を使います。接続先製品の独自プレイリストのシャッフル設定を変更するボタンではありません。

編集ウィンドウの「初期設定: ランダム再生」は、実行時に一度も切り替えていない場合のタブごとの初期値です。既存UIのボタンは「保存」またはPlay／Build時に自動追加します。

オンのタブは、手動で選んだ動画を最初に再生し、残りの有効な動画行をランダムな順番で一度ずつ再生して停止します。選んだ行より前の行も対象です。同じURLが複数の行にある場合は別の行として扱います。有効な動画が1件なら、その動画の終了で停止します。別の動画を手動選択すると、新しい順番で最初から開始します。

ランダムな順番を決めるシードと開始位置を再生位置と一緒に同期し、途中参加や所有者交代でも同じ順番を復元する設計です。実機での複数人同期は未検証です。

### 共通の動作

各プレイヤーの終了通知を受け取り、同期再生ではプレイヤーの所有者だけが次の動画を要求します。同じプレイヤーにつながる複数のUIは1つの連続再生状態を共有し、最後に選択した動画からの順序に切り替わります。途中参加や所有者交代に備えて、再生元UIと動画位置を同期します。ローカル再生モードのYamaPlayer/VizVidでは、そのクライアントだけで進みます。

手動停止や別URLへの切り替えで連続再生を解除します。エラーでは勝手に次へ進まず、プレイヤー本体が再試行して再生できた場合は継続します。ネイティブのキューがある場合はそのキュー経由で次の動画を要求するため、既にキューにある動画が先に再生される場合があります。単曲リピート中や終了通知のないライブ配信は次へ進みません。連続再生には単曲リピートをオフにしてください。

終了直後のプレイヤー内部処理と競合しないよう少し待ってから次を要求します。また、直前の読み込みから少なくとも約5秒空けます（他のプレイヤーとの共通制限までは調停しません）。接続先の権限で要求が拒否された場合は連続再生を停止します。

既存のシーンもPlay/Build時に接続を更新します。編集時に更新する場合はプレイリストの「保存」、または表示される「接続設定を修復」を実行してください。連続再生アダプターと終了通知用リスナーはプレイヤー本体のGameObjectへ自動配置します。以前のUI側アダプターは参照されなくなり、再生要求・終了通知を担当しません。

## プレイヤーごとの差異

| プレイヤー | 調査・コンパイル対象 | 接続先 | 再生経路 |
|---|---|---|---|
| iwaSync3 | 3.8.0 | HoshinoLabs.IwaSync3.Udon.VideoCore | 標準の権限条件→TakeOwnership→PlayURL→RequestSerialization |
| KineL | 2.5.5 | Kinel.VideoPlayer.Udon.KinelVideoPlayer | IsLock／Master確認→TakeOwnership→PlayByURL |
| VizVid | 1.8.2 | JLChnToZ.VRC.VVMW.FrontendHandler | Locked確認→PlayUrl（タイトル付き） |
| YamaPlayer | 2.0.0-beta.7 | Yamadev.YamaStream.UI.UIController | InvokeBeforeEvent(BeforeUserPlayTrack)→Controller.TakeOwnership→PlayTrack |

UdonSharpはWorlds SDK 3.10.5同梱実装を使用しています。独立パッケージの旧バージョン表記を推測していません。

- iwaSyncの`Stream Mode`は接続アダプターで設定します。オフはVIDEO=0x10、オンはSTREAM=0x20。標準キューが接続されていればPlayURLのキュー処理に従います。
- KineLは接続先で現在選択されている動画／ライブモードを使用します。モード変更は接続先のUIで行います。
- VizVidの`Player Index`は1始まりのバックエンド番号です（初期値1）。接続先のバックエンドに合わせて変更します。キューが有効なら既存のキュー動作に従います。
- YamaPlayerは接続したUIの権限リスナーに拒否権を渡します。UIのController参照をエディタで読み取り、アダプターへ保存します。UI側でControllerを変更した場合は「接続設定を修復」で更新します。現在のHandler設定と自動選択動作に従います。
- URLの対応サービス、ライブ配信、Android対応、URLフィルターなどの可否は各プレイヤーに依存します。共通UIはHTTP(S)の基本形式を確認しますが、再生可能性を保証しません。
- 再生時間やURL同期は各プレイヤーが管理します。共通側は連続再生の元UI・動画位置・変更番号・ランダム再生のシードと開始位置・実行時のモード選択を同期し、アダプターをプレイヤーの再生権限と同じGameObjectに配置します。

## 配布構成の理由

AVEC-Core、Playlist機能、4種類のプレイヤー用Connector、任意のExtensionに分離しています。機能側の実行コードにプレイヤー固有型の参照はありません。Editorの登録・候補検出は完全修飾型名を使い、実行時はUdonSharpでコンパイルした型付きアダプターを使います。

KineLのUdonアセンブリはautoReferenced=falseのため、Connectorから明示参照します。RuntimeアセンブリにはUnity asmdefと対応するU# Assembly Definitionを同梱します。必要な機能・接続先だけを導入する構成です。

配布物は本製品のコード・UI・データ・Udonプログラムと、OFLの表示を保持したフォントを含みます。プレイヤー本体やその素材、シーンは含めません。

## 再生成と検証

`Tools > AVEC > Playlist`にプログラムアセット生成、サンプルPrefab作成、検証シーン作成、UnityPackageエクスポートがあります。既存サンプルPrefabと検証シーンは自動上書きしません。通常の利用に再生成操作は不要です。

このプロジェクトでは `Tools > Common Assets > Release Builder` を使用してください。対象パッケージ・バージョン・出力先を指定し、「UnityPackage と ZIP を作成」でまとめて出力します。コンパイル済みProgramの配置、説明書付きZIP、SHA-256付きmanifestも自動で処理します。旧Exportメニューも同じ画面を開きます。通常の編集ごとに出力せず、配布が必要になった時だけ実行してください。別プロジェクト確認やPlayモードの動作テストは実行しません。EditorToolsパッケージを導入していない環境では旧メニューから個別出力します。

`VALIDATION.ja.md`に確認範囲、未確認事項と再検証手順を記載しています。Unityエディタの確認とVRChat実機・複数クライアントの確認は別です。
